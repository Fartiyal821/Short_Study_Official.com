1. The print() Function

print() is the first function almost every Python learner meets, and it's more configurable than it first appears. By default, print() writes its arguments to standard output, separated by a single space, and ends with a newline character. Both of those defaults can be overridden with the sep and end keyword arguments — sep controls what goes between multiple printed values, and end controls what's printed after the last value instead of the default newline.

print() can also accept any number of positional arguments, automatically converts non-string values to their string representation, and — since Python 3.6 — is commonly paired with f-strings (f"...") to embed expressions directly inside a string. It's worth remembering that print() always returns None; it displays output as a side effect, it does not hand back a usable value the way input() or a normal function call does.

# Customising sep and end print("Python", "is", "fun", sep="-", end="!\n") # Using an f-string name = "Aarav" print(f"Hello, {name}!")
OutputPython-is-fun! Hello, Aarav!

2. Variables

In Python, a variable is best understood not as a labelled box holding a value, but as a name bound to an object that exists independently in memory. When you write x = 10, Python creates an integer object 10 and makes the name x point to it — it doesn't copy the value into a container called x. This distinction matters once you start reassigning variables or working with mutable objects like lists, because two names can point to the exact same object.

Python supports multiple assignment in a single line (a, b, c = 1, 2, 3), chained assignment (a = b = c = 0), and augmented assignment (x += 1). Variable names are case-sensitive, can contain letters, digits, and underscores, but cannot start with a digit or match a reserved keyword. There is no variable declaration step in Python — a name comes into existence the moment it's first assigned a value.

# Multiple assignment a, b, c = 1, 2, 3 # Two names pointing to the same list object list1 = [1, 2, 3] list2 = list1 list2.append(4) print(list1) # list1 changes too!
Output[1, 2, 3, 4]

3. Data Types

Python is dynamically typed, meaning a variable's type is determined by the value currently assigned to it, and can change if reassigned. The core built-in types are int, float, complex, str, bool, and the special singleton None (of type NoneType). Beyond these, Python's built-in container types — list, tuple, set, and dict — are covered in depth later in this series.

A crucial distinction beginners often miss is mutability: int, float, str, bool, and tuple are immutable — once created, their value cannot change in place — while list, set, and dict are mutable. You can check a value's type at runtime with type(), and check whether it belongs to a type (including subclasses) with isinstance(), which is generally the preferred, more Pythonic approach.

# bool is actually a subclass of int in Python print(isinstance(True, int)) # True print(True + True) # 2
OutputTrue 2

4. The input() Function

input() pauses program execution, optionally displays a prompt string, waits for the user to type a response and press Enter, and then returns whatever was typed as a string — always, with no exceptions, even if the user types a number. This is one of the most common sources of bugs for beginners, who assume input() "knows" they wanted a number and are surprised when arithmetic on the result fails or behaves unexpectedly (string concatenation instead of addition).

To work with numeric input, you must explicitly convert the result using int() or float(). To accept multiple values on one line, a common pattern is combining input() with .split() to break the line into a list of strings, which can then be converted individually.

# WRONG: this concatenates strings, doesn't add numbers a = input("Enter first number: ") b = input("Enter second number: ") print(a + b) # e.g. "5" + "3" = "53", not 8 # CORRECT: cast to int first a = int(input("Enter first number: ")) b = int(input("Enter second number: ")) print(a + b) # 8

5. Type Casting

Type casting (or type conversion) is the process of converting a value from one data type to another. Python performs some conversions automatically — this is called implicit casting, and it happens, for example, when you add an int and a float together and Python automatically produces a float result. Explicit casting is when you deliberately convert a value using functions like int(), float(), str(), or bool().

Casting isn't always safe: int("abc") raises a ValueError because the string isn't a valid number, and int(3.9) truncates toward zero rather than rounding, giving 3 — not 4. Casting to bool() follows Python's "truthiness" rules: 0, 0.0, "", [], {}, and None are all falsy, while almost everything else is truthy.

# Implicit casting: int + float = float result = 5 + 2.0 print(result, type(result)) # Explicit casting: truncation, not rounding print(int(9.9)) # 9, not 10 print(bool("")) # False print(bool("0")) # True — non-empty string!
Output7.0 <class 'float'> 9 False True

6. Comments

Comments are lines that Python's interpreter ignores entirely — they exist purely for human readers. A single-line comment starts with # and extends to the end of the line. Python has no dedicated multi-line comment syntax, but developers commonly achieve the same effect by stacking multiple # lines, or by using a triple-quoted string ("""...""") as a standalone statement — though technically the latter is a string literal, not a comment, and is more properly reserved for docstrings, which document functions, classes, and modules and can be accessed programmatically via the __doc__ attribute.

Good commenting explains why code does something, not what it does — the "what" should be obvious from clear code itself. Over-commenting obvious code is considered a code smell just as much as under-commenting complex logic.

# This is a single-line comment def add(a, b): """This is a docstring, not a comment — it's stored and retrievable.""" return a + b print(add.__doc__)
OutputThis is a docstring, not a comment — it's stored and retrievable.

7. Keywords

Keywords are reserved words that form the syntax of the Python language itself — words like if, else, for, while, def, class, return, import, True, False, and None. Because they have fixed meaning to the interpreter, keywords cannot be used as variable, function, or class names — attempting to do so raises a SyntaxError. Python provides the built-in keyword module, which exposes keyword.kwlist, a list of every current keyword, useful for checking programmatically whether a given string is reserved.

Recent Python versions introduced soft keywords — words like match, case, and type that have special meaning only in specific syntactic contexts (like the match statement introduced in Python 3.10) but remain valid as ordinary identifiers elsewhere, unlike true keywords.

import keyword print(keyword.iskeyword("for")) # True print(keyword.iskeyword("match")) # False — it's a soft keyword print(len(keyword.kwlist)) # total number of keywords
OutputTrue False 35

8. Identifiers

An identifier is the name you give to a variable, function, class, module, or any other user-defined object. Python's rules for valid identifiers: they must start with a letter (a-z, A-Z) or an underscore, followed by any combination of letters, digits, and underscores; they cannot start with a digit; they cannot be a reserved keyword; and — since Python 3 — they can also include valid Unicode characters beyond the basic ASCII set, though this is rarely used in practice.

Python is case-sensitive, so score, Score, and SCORE are three entirely distinct identifiers. Beyond the language's hard rules, PEP 8 (Python's style guide) recommends conventions: snake_case for variables and functions, PascalCase for classes, and UPPER_SNAKE_CASE for constants — these are conventions, not enforced by the interpreter, but following them is considered a mark of idiomatic Python.

# Valid identifiers _private = 1 student_name = "Aarav" MAX_SIZE = 100 # These would raise a SyntaxError if uncommented: # 2nd_place = "silver" # class = "Physics"
